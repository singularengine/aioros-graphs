# Hierarchy

d3-hierarchy's hierarchies and layouts (`Hierarchy`, `Tree`, `Cluster`, `Treemap`, `Pack`, `Partition`). Golden
fixture: `Golden/hierarchy.json`, from `tools/golden/cases/hierarchy.mjs` (d3-hierarchy 3.1.2, the version d3 7.9.0
bundles). The trees are generated from a seeded random source; each node's name is its pre-order index, which is the
engine's node index for nested data. Every coordinate, radius and value is compared bit for bit.

| ID | Criterion |
|---|---|
| HIERARCHY-01 | Given each tree of the `structure` cases (a single node, one child, a flat root with many leaves, a chain, random trees of 12 to 400 nodes), when `Hierarchy.FromNested` builds it, then each node's parent, depth and height, the children of each node in order, `Descendants` (breadth first), `Leaves`, `PreOrder` (d3's `eachBefore`), `PostOrder` (d3's `eachAfter`), `Links` and the `Ancestors` of every node equal d3's `hierarchy()`. |
| HIERARCHY-02 | Given each tree of the `structure` cases, when `Path` runs between pairs of nodes (a node to itself, to its ancestor, to its descendant, across subtrees, to the root), then the nodes equal d3's `node.path(target)` in order. |
| HIERARCHY-03 | Given each tree and leaf values of the `values` cases (positive, zero, fractional and missing values, values on inner nodes), when `Sum` runs, then each node's value equals d3's `node.sum(d => d.value)` bit for bit, a missing (NaN) value counting as 0; and when `CountLeaves` runs, then each node's value equals d3's `node.count()`. |
| HIERARCHY-04 | Given a hierarchy, when `Sum` receives a span whose length differs from the node count, then an `ArgumentException` is thrown. |
| HIERARCHY-05 | Given each tree of the `sorts` cases summed, when `Sort` runs with each comparator (value descending, value ascending, height then value, a comparator that returns NaN for some pairs), then the children of every node come in the order of d3's `node.sort(compare)`, which sorts as V8's `Array.prototype.sort`, and the node indices, parents, depths, heights and values are unchanged. |
| HIERARCHY-06 | Given each row list of the `stratify` cases (ids and parent ids in any order, empty-string ids and parent ids that count as absent, rows without an id), when `Hierarchy.Stratify` runs, then each row's node has the parent, depth, height and children of d3's `stratify()`, rows keep their index as node index, and `Id` returns each node's id. |
| HIERARCHY-07 | Given each rejected row list of the `stratifyErrors` cases (a missing parent, an ambiguous parent id, two roots, no root, a cycle), when `Hierarchy.Stratify` runs, then an `ArgumentException` is thrown whose message is d3's error message (`missing: id`, `ambiguous: id`, `multiple roots`, `no root`, `cycle`). |
| HIERARCHY-08 | Given each path list of the `paths` cases (nested paths, missing intermediate directories, trailing and escaped slashes, a single path, paths whose common prefix becomes the root), when `Hierarchy.StratifyPaths` runs, then the nodes, their ids (imputed directories included), parents, depths, heights and children equal d3's `stratify().path(d => d)`, imputed nodes report no row (`Row` is -1) and imputed roots with one child are dropped as in d3. |
| HIERARCHY-09 | Given each parent-index list of the `parents` cases, when `Hierarchy.FromParents` runs, then the hierarchy equals d3's `stratify()` with each index as id and its parent index as parent id; and given a list with an index out of range, two roots, no root or a cycle, then an `ArgumentException` is thrown. |
| HIERARCHY-10 | Given each tree of the `tree` cases and each setting (default size, a size of 960 × 500, a node size of 12 × 80, d3's default separation and the radial separation `(a.parent == b.parent ? 1 : 2) / a.depth`, sorted and unsorted), when `Tree.Compute` runs, then each node's x and y equal d3's `tree()` (Reingold–Tilford, Buchheim's algorithm) bit for bit. |
| HIERARCHY-11 | Given each tree and setting of the `cluster` cases, when `Cluster.Compute` runs, then each node's x and y equal d3's `cluster()` bit for bit. |
| HIERARCHY-12 | Given each summed tree of the `treemap` cases and each tiling (squarify with the golden ratio and with ratios 1, 3 and 0.5, resquarify, binary, dice, slice, sliceDice), padding (none, uniform, inner and outer, a top padding with distinct right, bottom and left), size (960 × 500, 10 × 10, 100 × 0) and rounding, when `Treemap.Compute` runs, then each node's x0, y0, x1 and y1 equal d3's `treemap()` bit for bit, including nodes collapsed by padding and zero-valued nodes. |
| HIERARCHY-13 | Given a tree laid out with resquarify and then summed with new values (the `resquarify` cases), when `Treemap.Compute` runs again with the previous layout, then the rectangles equal d3's second `treemap(root)` call, which keeps the first layout's rows; and with squarify, or with a previous layout of another ratio, the rows are computed anew as in d3. |
| HIERARCHY-14 | Given each summed tree of the `pack` cases and each setting (sizes 960 × 960 and 800 × 600, padding 0 and 3, a leaf radius from each node's value), when `Pack.Compute` runs, then each node's x, y and r equal d3's `pack()` bit for bit, with d3's seeded random source for the enclosing circles. |
| HIERARCHY-15 | Given each radius list of the `packSiblings` cases (empty, one, two, three, many, zero radii), when `Pack.Siblings` runs, then each circle's x and y equal d3's `packSiblings` bit for bit and the returned radius is the enclosing circle's. |
| HIERARCHY-16 | Given each circle list of the `packEnclose` cases (one, two, three and many circles, nested and coincident circles), when `Pack.Enclose` runs, then the circle equals d3's `packEnclose` bit for bit; and given no circle, then `false` is returned, as d3 returns undefined. |
| HIERARCHY-17 | Given each summed tree of the `partition` cases and each setting (default size, 960 × 500, a sunburst's 2π × radius, padding 0 and 1, rounding), when `Partition.Compute` runs, then each node's x0, y0, x1 and y1 equal d3's `partition()` bit for bit. |
| HIERARCHY-18 | Given `Pack.Compute` with a leaf radius list whose length differs from the node count, `Pack.Siblings` with coordinate spans shorter than the radii, or `Treemap.Compute` with a previous layout of a hierarchy of another node count, when each is called, then an `ArgumentException` is thrown; sizes, paddings and ratios are taken as d3 takes them. |
