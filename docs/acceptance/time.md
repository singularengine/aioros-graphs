# Time

d3-time's UTC and local intervals and ticks (`UtcCalendar`, `UtcInterval`, `UtcTicks`, `LocalCalendar`,
`TimeInterval`, `TimeTicks`) on JavaScript time values: milliseconds since the Unix epoch as doubles, clipped to whole
milliseconds and to ±8.64e15 as `Date` does. Local time is read in a `TimeZoneInfo` (the local zone by default) with
`Date`'s local semantics. Golden fixtures: `Golden/time.json`, from `tools/golden/cases/time.mjs`, and
`Golden/localtime.json`, from `tools/golden/cases/localtime.mjs`, which runs d3 once per time zone (UTC,
Europe/Berlin, America/Mexico_City, America/Sao_Paulo, Australia/Lord_Howe, Asia/Kolkata, America/New_York) with the
zone's first daylight-saving transitions found in 1996 to 2024.

| ID | Criterion |
|---|---|
| TIME-01 | Given each date of the `fields` cases (leap days, month and year ends, before 1970, years below 100 and negative, the edges of the representable range), when `UtcCalendar` reads its year, month, day, weekday, hours, minutes, seconds and milliseconds, then they equal the `Date`'s `getUTC*` values, and composing fields that overflow (month +14, day -40, hours +30, minutes -5, seconds 70, milliseconds 1500) gives `Date.UTC`'s value. |
| TIME-02 | Given each interval (millisecond, second, minute, hour, day, Unix day, the weeks starting on each day from Sunday to Saturday, month, year), step and date of the `interval` cases, when `Floor`, `Ceil`, `Round` and `Offset` (by -3, -1, 0, 1, 2.7 and 13) run on `UtcInterval` and its `Every(step)`, then each result equals d3's, the filtered intervals keeping d3's field or count test and the millisecond and year intervals their specialized steps. |
| TIME-03 | Given each interval and step of the `every` cases, when `Every` runs, then it returns no interval exactly where d3's `every` returns null: zero, negative, NaN and infinite steps, and steps that floor to zero. |
| TIME-04 | Given each interval and pair of dates of the `counts` cases, when `Count(start, end)` runs, then it returns d3's `interval.count(start, end)`. |
| TIME-05 | Given each interval, span and step of the `ranges` cases (empty spans and steps below one included), when `Range(start, stop, step)` runs, then it returns d3's `interval.range(start, stop, step)`, and the span overload writes the same values. |
| TIME-06 | Given each span and count of the `ticks` cases (from milliseconds to two thousand years, ascending and descending), when `UtcTicks.Ticks` and `UtcTicks.TickInterval` run, then the ticks equal d3's `utcTicks(start, stop, count)` and an interval is returned exactly when `utcTickInterval` returns one; the span overload `UtcTicks.Ticks(start, stop, count, destination)` writes the same ticks, and `UtcTicks.MaxCount` is at least their number. |
| TIME-07 | Given each span and count of the `nice` cases, when the span is extended to `UtcTicks.TickInterval`'s floor and ceiling as `UtcTicks.Nice` does, then the bounds equal d3's `scaleUtc().domain([start, stop]).nice(count).domain()`. |
| TIME-08 | Given a UTC scale over 2024 and over two years, warmed up, when its ticks are written with `UtcScale.Ticks(count, destination)` into a stack buffer and each tick is labelled with `UtcTimeFormat.TryMultiScale` and with a compiled `%Y-%m-%d` format's `TryFormat` into a stack buffer, then no managed memory is allocated (the thread's allocated bytes do not change). |
| TIME-09 | Given each zone and date of the local `fields` cases (dates around daylight-saving transitions, half-hour offsets and an invalid date), when `LocalCalendar` reads the offset, year, month, day, weekday, hours, minutes, seconds and milliseconds, then they equal the `Date`'s `getTimezoneOffset` and local getters, NaN for the invalid date. |
| TIME-10 | Given each zone and fields of the local `compose` cases (local times inside daylight-saving gaps, repeated local times, overflowing fields, a two-digit year, the end of the range and NaN), when `LocalCalendar.Compose` runs, then it returns `new Date(year, month, ...)`'s value: a time in a gap moved forward by the offset before the transition, a repeated time at its first occurrence, years 0 to 99 in the 1900s, NaN outside the range. |
| TIME-11 | Given each zone, interval (second, minute, hour, day, the weeks starting on each day from Sunday to Saturday, month, year), step (1 and 3) and date of the local `interval` cases, when `Floor`, `Ceil`, `Round` and `Offset` (by -3, -1, 0, 1, 2.7 and 13) run on `TimeInterval.WithZone(zone)` and its `Every(step)`, then each result equals d3's local interval (`timeDay`, `timeMonday`, ...), including across daylight-saving transitions. |
| TIME-12 | Given each zone, interval and pair of dates of the local `counts` cases, and each span and step of the local `ranges` cases, when `Count` and `Range` run, then they return d3's `interval.count` (days and weeks corrected by the change of offset) and `interval.range`, and the span overload of `Range` writes the same values. |
| TIME-13 | Given each zone, span and count of the local `ticks` cases (spans across daylight-saving transitions, hours to thirty years), when `TimeTicks.Ticks` runs in both directions and `TimeTicks.TickInterval` runs, then the ticks equal d3's `timeTicks(start, stop, count)`, an interval is returned exactly when `timeTickInterval` returns one, the span overload writes the same ticks and `TimeTicks.MaxCount` is at least their number. |
| TIME-14 | Given the local interval, ticks and calendar with no zone given, when they run, then they use `TimeZoneInfo.Local`: `TimeInterval.Day.Zone` is the local zone, and `TimeTicks.Ticks` and `TimeInterval.Day.Floor` return what they return with `TimeZoneInfo.Local` given explicitly; `TimeInterval.WithZone` and `LocalCalendar` with a null zone throw `ArgumentNullException`. |
