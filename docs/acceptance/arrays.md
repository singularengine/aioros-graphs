# Arrays

The d3-array functions charts need: `ticks`, `tickIncrement`, `tickStep`, `nice`, the bisectors (on values and on
keys), `extent`, the summary statistics, `fcumsum` and `Adder`, quantiles, `bin` with its threshold rules, `range`,
`group` and `rollup` with one or several levels of keys, `flatGroup`, `flatRollup` and `index`.
Golden fixture: `Golden/array.json`, from `tools/golden/cases/array.mjs`. Undefined results are NaN (or -1 for an
index), as `Extent` already returns them.

| ID | Criterion |
|---|---|
| ARRAY-01 | Given each start, stop and count of the `ticks` cases (ascending, descending, equal bounds, fractional, zero, negative and NaN counts, tiny and huge spans), when `Ticks.Compute` runs, then it returns exactly d3's `ticks(start, stop, count)`, bit for bit, `Ticks.Count` returns their number and the span overload writes the same values. |
| ARRAY-02 | Given each case of the `increments` cases, when `Ticks.Increment` and `Ticks.Step` run, then they return exactly d3's `tickIncrement` and `tickStep`. |
| ARRAY-03 | Given ascending values with duplicates and each probe of the `bisect` cases (below, between, equal to and above the values, NaN and -Infinity), when `Bisect.Left`, `Bisect.Right` and `Bisect.Center` run, then they return d3's `bisectLeft`, `bisectRight` and `bisectCenter`. |
| ARRAY-04 | Given each list of the `extent` cases (with NaN, empty, only NaN, signed zeros, infinities), when `Extent.Of` runs, then it returns d3's `extent`, with (NaN, NaN) where d3 returns undefined bounds. |
| ARRAY-05 | Given each list of the `quantile` cases (empty, NaN only, one value, ties, signed zeros, infinities, 1,000 samples) and each p (below 0, 0, fractions, 1, above 1, NaN), when `Quantiles.Of`, `Quantiles.OfSorted` (on the sorted numbers) and `Quantiles.IndexOf` run, then they return d3's `quantile`, `quantileSorted` and `quantileIndex` bit for bit (NaN and -1 where d3 returns undefined), following d3's quickselect so the sign of a zero is d3's too. |
| ARRAY-06 | Given each list of the `statistics` cases, when `Statistics.Sum`, `Mean`, `Median`, `Min`, `Max`, `MinIndex`, `MaxIndex`, `Variance`, `Deviation` and `FSum` run, then each returns d3's value bit for bit: NaN skipped, NaN where d3 returns undefined, -1 for the index of an empty list, Welford's variance and Python's exact `fsum` partials. |
| ARRAY-07 | Given each list of the `statistics` cases, when `Statistics.CumulativeSum` writes the running sums, then they equal d3's `cumsum` (NaN counted as zero), and a destination shorter than the values throws an `ArgumentException`. |
| ARRAY-08 | Given each list of the `statistics` cases with its extent, when `ThresholdRule.Sturges`, `Scott` and `FreedmanDiaconis` count the bins, then the counts equal d3's `thresholdSturges`, `thresholdScott` and `thresholdFreedmanDiaconis` (1 when the spread or the count is zero). |
| ARRAY-09 | Given each list of the `bin` cases with a count or a rule as thresholds and the default domain, when `Histogram.Compute` bins it, then the bins' `X0`, `X1` and members equal d3's `bin()`: the domain niced to the tick increment, the last bound extended by one step when the maximum falls on it, values assigned by quantization, NaN skipped, a single bin for equal or no values. |
| ARRAY-10 | Given each list of the `bin` cases with explicit threshold values or an explicit domain, when `Histogram.Compute` bins it, then the bins equal d3's: no nicing, thresholds outside the domain dropped, values outside the domain skipped, values placed by bisection. |
| ARRAY-11 | Given a histogram, when the span receiving each value's bin is shorter than the values, then an `ArgumentException` is thrown, and values outside every bin get -1. |
| ARRAY-12 | Given each start, stop and step of the `range` cases (fractional, descending, empty, zero and NaN steps), when `Sequence.Range` runs, then it returns d3's `range(start, stop, step)` bit for bit. |
| ARRAY-13 | Given each start, stop and count of the `nice` cases, when `Ticks.Nice` runs, then it returns d3's `nice(start, stop, count)`. |
| ARRAY-14 | Given the keys of the `group` cases (strings with null and empty keys, numbers with NaN and signed zeros), when `Grouping.Group` groups their indices, then the groups come in d3's `group` order (first appearance) with d3's members, NaN keys grouped together and -0 merged into 0 as JavaScript's `Map` does. |
| ARRAY-15 | Given the keys and values of the `rollup` cases, when `Grouping.Rollup` reduces each group with the sum, mean, count, min, max and median reducers, then the keys and values equal d3's `rollup`. |
| ARRAY-16 | Given objects ascending by a key and each probe of the `bisector` cases (below, between, equal, above, NaN, -Infinity), when `Bisector.Left`, `Right` and `Center` search them through a key selector, then they return d3's `bisector(d => d.x)` indices. |
| ARRAY-17 | Given the items of the `nestedGroup` cases with two and three levels of keys (strings with null and empty keys, numbers with NaN and signed zeros), when `Grouping.GroupNested` groups their indices, then each level's groups, keys and members equal d3's `group(data, ...keys)` (first-appearance order within each parent group, members ascending); and given levels of different lengths or no level, an `ArgumentException` is thrown. |
| ARRAY-18 | Given the keys and values of the `nestedRollup` cases, when `Grouping.RollupNested` reduces each innermost group with the sum, count and median reducers, then the nested keys and values equal d3's `rollup(data, reduce, ...keys)`. |
| ARRAY-19 | Given the cases of `nestedGroup` and `nestedRollup`, when `Grouping.FlatGroup` and `Grouping.FlatRollup` run, then each row's keys and members (or value) equal d3's `flatGroup` and `flatRollup`, in their order. |
| ARRAY-20 | Given the keys of the `index` cases, when `Grouping.Index` runs, then each key maps to its item's index in d3's `index` order; and given a key that appears twice, an `InvalidOperationException` is thrown, as d3 throws "duplicate key". |
| ARRAY-21 | Given each list of the `statistics` cases, when `Statistics.FCumulativeSum` writes the running full-precision sums and an `Adder` adds the values one by one, then they equal d3's `fcumsum` and `new Adder().add(...)` bit for bit, NaN counted as zero; and a destination shorter than the values throws an `ArgumentException`. |
